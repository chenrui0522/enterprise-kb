## ADDED Requirements

### Requirement: 考勤汇总台账实现必须可运行并可提交
系统 SHALL 提供与已归档主规格一致的可运行考勤汇总台账实现（API、领域计算、确认与正式导出）。该实现的源文件 MUST 存在于仓库工作区并可被正常导入；MUST NOT 仅依赖 `__pycache__` 或残缺反编译文件作为唯一运行形态。具备权限的操作者 MUST 能完成：选定目标月、设置 prior/花名册底表、上传三源、处理阻塞告警、确认并下载太原模板正式台账。

#### Scenario: 对话/API 主路径可完成一月任务（Phase A）
- **WHEN** 具备考勤汇总写入权限的操作者经对话工具（或等价 API）为某目标月完成 prior（或冷启动花名册）、三源上传、必要告警决议并确认
- **THEN** 系统允许下载太原模板正式 xlsx，且任务状态为已确认、可作为后续 prior

#### Scenario: 专页主路径可完成一月任务（Phase B 延后）
- **WHEN** Phase B 恢复独立考勤汇总台账页后，操作者在专页完成同上主路径
- **THEN** 系统同样允许正式导出与确认状态（与对话口径一致）；Phase A MUST NOT 因专页未恢复而阻塞对话验收

#### Scenario: 源码可导入
- **WHEN** 服务进程加载考勤汇总领域模块与 API 路由
- **THEN** 加载成功且不因缺失源文件或仅有 pyc 而失败

### Requirement: 证据化增量行为可恢复
系统 SHALL 恢复下列增量行为中、能经 `__pycache__`、对话进度卡动作或未归档 change 文案交叉验证的部分；无法验证的行为 MUST NOT 伪称已交付：
1. **任务年月/期间选择**：允许显式指定目标月（非仅默认自然月）。
2. **应出勤日历确认/编辑**：在计算依赖月历前，允许操作者确认或调整公司应出勤日集合（以证据存在的动作为准）。
3. **打卡与出差细则**：含出差期间打卡半休/驻地裁剪/应出勤与出差拆分等已在字节码或规格草稿中出现的规则。
4. **审计/工作簿类导出**：若证据表明存在预览或审计用工作簿，则与正式导出区分且不得充作 prior。

#### Scenario: 可指定非默认月份
- **WHEN** 操作者在专页或对话中指定某年月为考勤汇总目标月并完成计算
- **THEN** 日格与红框仅覆盖该目标月

#### Scenario: 未验证增量不冒充完成
- **WHEN** 某增量仅有空 change 目录或文案、且 pyc/UI 无对应动作证据
- **THEN** 系统不得在发布说明或界面中声称已支持该增量

## ADDED Requirements

### Requirement: 考勤汇总对话工具必须可运行
系统 SHALL 恢复问答中的「考勤汇总台账」工具编排，使行为与已归档 `chat-tools` 考勤相关要求一致：按权限展示工具、显式认领与 sticky job、与调休含糊时先澄清、对话内完成与专页同口径的主路径（年月、prior、三源、告警决议、二次确认、导出）、以及对当前任务的只读问答。对话进度卡所暴露的动作（含 prior、冲突/HR 决议、日历/期间相关动作若已证据化）MUST 绑定真实后端动作，MUST NOT 仅残留前端死按钮。

#### Scenario: 对话可选工具并建任务
- **WHEN** 用户具备考勤汇总权限并在工具下拉选中「考勤汇总台账」后开始上传三源之一
- **THEN** 系统进入考勤汇总工作流并更新任务进度卡，而非因模块缺失报错或静默失败

#### Scenario: 进度卡动作可达后端
- **WHEN** 用户在考勤汇总进度卡点击已证据化的动作（如确认、作废、导出、合并 prior、冲突决议）
- **THEN** 系统调用对应考勤汇总工具动作并返回更新后的卡片或错误说明

#### Scenario: 独立专页入口恢复（本 change Phase B 延后）
- **WHEN** 具备考勤汇总权限的用户在 Phase A 期间打开原专页路由
- **THEN** 系统 MUST NOT 因缺失专页组件导致整站白屏（可重定向或占位）；完整专页上传/决议/确认/导出 MUST 在 Phase B 恢复，不阻塞本阶段「对话里能算能导出」验收

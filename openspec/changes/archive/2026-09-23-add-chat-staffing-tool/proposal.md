## Why

人员投入已有独立页与 API，但刘珊等业务用户的主习惯是「在对话里丢日报、说需求」；当前问答只能做知识库检索，composer 无工具入口与附件，工作流无法在对话中完成。需要把人员投入挂成问答旁的可扩展工具，并支持话术+表格自动触发。

## What Changes

- 在问答输入区旁增加 **工具下拉**（红框位置）：按权限列出可用工具；首期工具为「人员投入」，预留后续工具注册位。
- Composer 支持附件（至少 `.xlsx`）；用户可显式选工具，或在未选择时凭 **附件+话术** 自动走人员投入（规则强则直达，弱则先确认——M3）。
- 同一会话内完成人员投入工作流：导入解析 →（告警）对话复核 → 确认入库 → 汇总回复；支持查询汇总与作废，**确认入库/作废须二次确认**。
- 复用现有 `staffing:*` API 与项目成员授权；不重写解析/事实模型。
- **保留** `/staffing` 独立页（P1）作为点选备用；顶栏入口可保留，主路径为对话。
- 非目标：整站左导航大改、通用 LLM function-calling 平台、其它业务工具的完整实现、外部外包统计。

## Capabilities

### New Capabilities

- `chat-tools`: 问答工具注册与权限过滤、composer 工具下拉与附件、意图路由（显式选择 / 强规则自动 / 弱规则确认）、在会话中调用人员投入工作流并以卡片/消息呈现结果与确认动作。

### Modified Capabilities

- `multi-turn-chat`: 会话消息可包含附件与工具工作流回合；同一会话内可延续「人员投入」上下文（当前批次、项目）。
- `knowledge-qa`: 当本轮由人员投入（或其它已注册工具）认领时，MUST NOT 仅用文档检索臆造出勤人数/天数；出勤事实 MUST 来自人员投入能力。

## Impact

- 前端：`ChatPage` composer（工具下拉、附件、确认/汇总卡片）；可选弱化对独立页的依赖说明。
- 后端：chat 路径增加附件暂存与工具编排（调用既有 staffing service/API）；权限仍为 `staffing:read`/`staffing:write` + 项目成员。
- 观测：工具触发/确认/作废沿用或扩展既有 staffing 审计与 ops 事件。
- 独立 `/staffing` 页本期不删除。

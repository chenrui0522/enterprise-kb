## Context

见 proposal.md。现状：图片接口返回原图（`image/jpeg`，单张最大约 2.4MB），引用区用 64px 缩略图直接引用原图地址，点击在新标签打开。

## Goals / Non-Goals

**Goals:** 引用区可在页面内浏览图片；缩略图加载快且不拖垮页面；实现集中在图片接口与聊天页。
**Non-Goals:** 文档级画廊（B 方案）、图片编辑/删除、以图搜图、VLM 描述。

## Decisions

### D1 缩略图按需生成并缓存

`GET /documents/{id}/images/{image_id}?w=200` 时用 Pillow 生成缩略图，缓存到 `data/thumbnails/<sha256>_w<width>.jpg`（原子写：先写临时文件再替换），命中缓存直接返回；不带 `w` 时行为不变（返回原图）。

### D2 宽度约束

只允许 `64 / 200 / 400 / 800` 四档（实现上取最接近且不超过请求值的档位），避免任意尺寸导致缓存膨胀或内存放大。

### D3 不支持缩放的格式回退

EMF/WMF 等 Pillow 打不开的格式直接返回原图，并在响应头标注未经缩放，前端仍可展示。

### D4 lightbox 自包含在聊天页

`ChatPage` 内维护 `lightbox` 状态（当前消息的图片列表 + 索引）；缩略图点击打开，键盘 ←/→ 切换、Esc 关闭、点击遮罩关闭；图片列表来自该消息所有引用的 `images` 扁平化。

### D5 缩略图宽度与放大图宽度

引用区缩略图用 `w=200` 且 `loading="lazy"`；lightbox 放大查看用 `w=800`（比原图快，同时足够清晰），点击"查看原图"仍可打开原图地址。

## Risks / Trade-offs

- [缩略图缓存增长] → 缓存键含 sha256 与宽度，后续可按文档版本清理；本期先记录。
- [并发生成同一缩略图] → 原子写 + 命中即返回，最坏情况重复生成一次。
- [大图列表拖慢页面] → 懒加载 + 缩略图宽度限制。

## Migration Plan

无数据迁移；部署后前端与 API 同版本升级即可。回滚：前端改回直接引用原图地址。

## ADDED Requirements

### Requirement: 短期与长期记忆分层
系统 SHALL 同时维护滑动窗口形式的短期记忆与压缩摘要形式的长期记忆。长期记忆 MUST 在**未压缩窗口消息合计 token**超过配置预算（`KB_MEMORY_TOKEN_BUDGET`）时触发压缩；窗口 MUST 保留最近若干轮未压缩消息。滚动摘要 MUST 遵守配置的摘要硬顶（`KB_SUMMARY_TOKEN_CAP`）。压缩 MUST 以异步方式执行：聊天响应 MUST NOT 因压缩而阻塞；超预算时 MUST 入队并由后台 worker 完成摘要写入与消息标记。

#### Scenario: 超过窗口 token 预算触发压缩
- **WHEN** 未压缩窗口消息的合计 token 超过配置的 `KB_MEMORY_TOKEN_BUDGET`
- **THEN** 系统将窗口外最旧的一段消息压缩为长期摘要，并保持窗口内有最近若干轮消息

#### Scenario: 窗口内会话
- **WHEN** 未压缩窗口合计未超过 token 预算
- **THEN** 系统只使用滑动窗口，不产生摘要

#### Scenario: 摘要硬顶
- **WHEN** worker 生成的滚动摘要超过 `KB_SUMMARY_TOKEN_CAP`
- **THEN** 系统截断或再压缩摘要，使其不超过硬顶后再持久化

#### Scenario: 压缩不阻塞聊天
- **WHEN** 本轮对话触发压缩入队
- **THEN** 聊天流式响应在消息落库后正常结束，摘要由 worker 稍后写入

### Requirement: 压缩保留原文
系统 SHALL 仅将已压缩消息标记为已压缩并从滑动窗口移出；原文 MUST 永久保留且可通过会话历史查询。

#### Scenario: 查询已压缩消息
- **WHEN** 用户回溯较早的对话内容
- **THEN** 系统仍能返回完整原文，而不是只有摘要

### Requirement: 三层拼接上下文
系统加载会话上下文时 MUST 按"长期记忆摘要 + 未压缩的最近消息 + 当前问题"拼接；查询改写与答案生成 MUST 使用该拼接结果。

#### Scenario: 跨天恢复
- **WHEN** 用户在新的一天使用同一会话标识继续对话
- **THEN** 系统加载长期摘要与未压缩的最近消息，回答能够延续此前上下文

#### Scenario: 无摘要会话
- **WHEN** 会话尚未产生摘要
- **THEN** 系统退化为纯滑动窗口并正常工作

### Requirement: 会话标识稳定传递
前端 MUST 在每次请求中显式传递稳定的会话标识；系统 MUST 校验该标识的归属，标识不存在时 MUST 返回明确错误而不是静默新建会话。

#### Scenario: 同一会话标识继续对话
- **WHEN** 用户使用同一会话标识再次提问
- **THEN** 系统在该会话下追加消息并延续上下文

#### Scenario: 无效会话标识
- **WHEN** 前端传递了不存在或不属于当前租户的会话标识
- **THEN** 系统返回明确错误，不创建新会话

### Requirement: 对话状态不依赖缓存
会话与消息、长期摘要、LangGraph checkpoint MUST 持久化在数据库中；缓存层被清空 MUST NOT 影响会话恢复。

#### Scenario: 清空缓存后恢复
- **WHEN** 清空 Redis 并重启服务后使用同一会话标识继续对话
- **THEN** 系统仍能加载历史摘要与最近消息并正确继续对话

### Requirement: 会话记忆主界面可见
系统 MUST 在聊天主界面以只读方式展示当前会话的最新长期摘要（如侧栏「会话记忆」）；无摘要时 MUST 隐藏该区域或展示空态。用户 MUST NOT 通过该界面编辑或清空摘要。完整对话原文仍通过消息历史提供。

#### Scenario: 有摘要时主界面展示
- **WHEN** 会话已产生长期摘要且用户打开该会话的聊天页
- **THEN** 主界面展示最新版摘要正文，并标明其为压缩摘要而非完整记录

#### Scenario: 无摘要时不打断聊天
- **WHEN** 会话尚未产生摘要
- **THEN** 主界面不展示摘要正文（隐藏或空态），聊天与消息历史仍正常可用

#### Scenario: 摘要只读
- **WHEN** 用户查看会话记忆区域
- **THEN** 界面不提供编辑或清空摘要的操作

### Requirement: 压缩自观测
系统 MUST 对压缩路径发出可解析的运维事件，至少包括预算检查、入队、完成（含是否触发摘要硬顶）与失败；MUST 提供自动化探针：在会话中埋入可检验实体并触发压缩后，追问仍能命中该实体（回答与只读摘要接口）。系统 MUST NOT 根据观测结果自动修改 token 预算配置。

#### Scenario: L1 健康度事件可观测
- **WHEN** 发生预算检查、压缩入队、压缩完成或压缩失败
- **THEN** 系统发出对应结构化日志事件，字段足以判断是否超预算、摘要是否触顶、以及任务成败

#### Scenario: L2 压缩后实体仍可追问
- **WHEN** 探针会话先写入可检验实体，对话触发压缩且 worker 完成后用户追问该实体
- **THEN** 系统回答仍包含该实体，且只读摘要接口返回的最新摘要也能体现该实体（或等价关键信息）

## Why

人员投入姓名目前完全来自日报解析，PDF 换行/抽表常把全名拆成碎片或留下噪声；虽已提供《人员信息表》花名册，却只在导出时补「部门/职务」，汇总里仍会出现对不上的错误姓名。需要在导入阶段按花名册纠名，无法唯一确认的进入人工复核，避免错名入库。

## What Changes

- 导入解析后、写入待确认批次前，用配置的人员信息花名册（`KB_STAFFING_ROSTER_PATH` / 默认 `./data/staffing_roster.xlsx`）校正内部员工姓名。
- **精确命中**花名册姓名：原样保留。
- **唯一可纠**：解析短名是某花名册全名的前缀或后缀且仅唯一候选时，自动改成花名册全名，并记录可追溯的纠名告警/日志（不阻断确认）。
- **无法确认**（不在册、短名对应多个全名、拆名对不上任何册上姓名等）：产生须决议告警，批次进入待复核；告警未决议前 MUST NOT 确认入库。
- 复核决议至少支持：选定花名册姓名、手工改名、丢弃该 token（当日不计该人）。
- 身份（正式我司 / 机电服务处）仍由日报列源判定，不由花名册部门改写。
- 花名册缺失或无法加载时：批次 MUST 待复核并提示配置花名册，MUST NOT 在无花名册时静默跳过纠名直接确认（严格保证「入库姓名可对花名册」）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `staffing-daily-import`: 增加导入时花名册姓名校正与无法确认时的人工复核闸门；扩展脏数据复核告警类型与决议选项。独立页与对话导入共用同一解析/确认服务，对话侧无需单独改规格。

## Impact

- 后端：`app/staffing/parse.py`（或紧随其后的校正层）、`app/staffing/roster.py`（纠名 API）、`app/staffing/service.py`（告警决议与确认闸门）、相关 schema / 前端复核 UI。
- 配置：沿用已有花名册路径；运维须保证花名册文件可读。
- 测试：解析夹具覆盖精确命中、唯一纠名、歧义/不在册复核、无花名册不可确认。
- 无 **BREAKING** API 路径变更；已入库历史事实不回溯自动改名（仅新导入批次生效）。

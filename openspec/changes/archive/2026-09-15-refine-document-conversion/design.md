## Context

动机见 proposal.md。现状要点：PDF 由 PyMuPDF 提平文本、pdfplumber 表格追加到页尾；扫描件仅整篇无文字层才回退 MinerU；DOCX 用 python-docx，含媒体时改走 MinerU；XLSX 经 MarkItDown 转大表；转换失败已由 `convert_safely` 归一为带上下文的 AppError。

## Goals / Non-Goals

**Goals:** 每种格式走最合适的转换路径；转换失败可回退、可观测；表格与 Office 内容检索友好；重导不重复解析。
**Non-Goals:** VLM 语义描述、图片内容检索、检索侧排序策略调整。

## Decisions

### D1 分诊优先，重解析器按需调用

`triage.py` 用轻量探测决定路由：PyMuPDF 按页判断文字层与图片数量，pdfplumber 判断表格存在性；扫描页/含表格公式的 PDF → MinerU；其余文字 PDF → Docling；Docling 不可用或失败 → 现有本地解析。分诊结果与最终转换器写入转换报告。

替代方案：所有 PDF 走同一解析器。放弃原因是 Docling 与 MinerU 的强项不同，统一会牺牲质量或成本。

### D2 Docling 以独立 HTTP 服务部署

与 MinerU 同构：容器内运行 Docling 服务，暴露 `POST /convert`（multipart，参数含表格/OCR 开关）与 `GET /health`；worker 通过 `KB_DOCLING_URL` 调用，返回结构化块映射到统一 Block（含页码与位置）。服务不可用时自动跳过该候选。

替代方案：进程内库。放弃原因是模型推理会拖慢/阻塞 worker，且升级与限流困难。

### D3 DOCX 保持 python-docx 自定义并补齐图片顺序

按段落顺序遍历文档，跟踪最近的标题作为章节，图片通过 `w:drawing//a:blip` 的关系映射按出现顺序抽取并挂到该章节；复杂媒体文档仍可选 MinerU。

### D4 XLSX 语义化模板（通用自动推断）

每个 sheet 一节：跳过隐藏/空白表；用"首个非空行 + 类型一致性"推断表头；合并单元格向下填充；逐行生成 `【sheet】字段=值；…` 语义文本；公式取计算值；超长表按行分组并重复表头。语义行作为切片文本，表格结构仅作为元数据，避免重复索引。

替代方案：继续输出 Markdown 大表。放弃原因是宽表/长表检索效果差、引用粒度粗。

### D5 转换报告随文档版本持久化

新增字段记录：转换器与版本、分诊依据、是否降级、页数、表格数、图片数、耗时。用于区分"转换失败"与"检索未命中"，并支撑后续按版本对比质量。

### D6 解析缓存内容寻址

缓存键 = 文件 sha256 + 转换器 + 转换器版本 + 关键参数；缓存内容为结构化结果（可序列化），命中则跳过解析。缓存目录随文档存储，按需清理。

## Risks / Trade-offs

- [Docling 引入新依赖与模型体积] → 独立服务 + 模型缓存卷；先用基线评测确认收益再启用。
- [分诊误判] → 记录分诊依据，支持按文档类型覆盖；失败自动回退下一候选。
- [XLSX 表头推断错误] → 表头行与语义字段写入转换报告，便于抽样核查；保留原始 sheet 名与行号。
- [缓存失效判断不当] → 键包含转换器与参数，任一变化即重新解析。

## Migration Plan

1. 新增转换报告字段与缓存目录（迁移 0007）。
2. 部署 docling 服务（可选 profile），配置 `KB_DOCLING_URL`。
3. 灰度：对新上传文档启用分诊；对历史文档通过 reindex 逐步重解析（缓存命中则复用）。
4. 回滚：关闭分诊开关即回到现有本地解析路径。

## Open Questions

- Docling 的表格识别与本地方案在真实语料上的差异（需基线评测后定）。
- XLSX 语义文本是否需要同时保留紧凑表格（取决于检索评测结果）。

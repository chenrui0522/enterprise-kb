## Why

项目部工作台 V1 首批业务要回答最迫切问题：某项目上**公司内部员工**去了哪些人、每人去了多少天。现场数据源是「项目日报表」Excel（按日一行；内部员工人名来自「现场施工人员/人数」中的公司段，以及右侧「我司人员」姓名格）。脏数据（解析含糊、项目号认不准、双源冲突等）必须人工复核确认后才能进正式汇总，并支持按日/按人/按批回退。导入、复核、确认与作废纳入既有运维日志与审计。

## What Changes

- 新增「人员投入」能力：上传项目日报 xlsx → 解析内部员工 →（有问题时）人工复核 → 确认后写入出勤事实 → 按项目汇总「有谁 / 在场天数」。
- 从文件名/标题自动匹配已授权项目；匹配失败或歧义则进入复核，禁止瞎绑。
- **仅统计公司内部员工**：来源为 C 列【公司人员】与右侧「我司人员」姓名格（含用工为外包性质的我司人员）；汇总可区分「正式我司」与「我司·外包性质」。
- **不统计**外部外包队（C 列【外包人员】有名/无名一律忽略）；不做未具名外包 Y/Z。
- 出勤以可软作废的事实为原子单位；支持按日×人、按人（项目全量）、按导入批次作废；重传确认时对重叠日期作废旧事实并写入新事实，非重叠旧日保留。
- 补齐人员投入路径的运维阶段事件与写操作审计，复用现有 JSON ops 与 `audit_events` / Admin 审计页。
- 非目标：外部外包投入统计、ERP 岗位→阶段、施工计划总窗驱动、计划对比/进度表串联、造假人名、计划图/指标测算/文档草稿/门禁。

## Capabilities

### New Capabilities
- `staffing-daily-import`: 项目日报导入解析（仅内部员工）、项目自动匹配、脏数据复核、出勤事实确认与按日/按人/按批回退、按项目汇总有谁与在场天数。

### Modified Capabilities
- `ops-observability`: 增加人员投入路径关键阶段运维事件（解析、认项目、待复核、确认、作废等）与耗时/状态字段约定。
- `identity-access`: 扩展关键写操作审计，覆盖人员投入导入、复核决议、确认与作废类动作，仍经现有审计查询与管理端查阅。

## Impact

- 后端：新增 personnel/staffing 模块（解析、批次、事实、汇总、作废 API）；Alembic 表与迁移；权限挂已授项目。
- 前端：导入/复核/汇总与按日·按人·批次作废入口；加密或非标准 xlsx 明确拒收提示。
- 观测：沿用 `log_event` / `timed_event` / `write_audit`；运维日志不对日报全文落盘（预览截断）。
- 样表参考：桌面可读副本「项目日报1.xlsx」（原 `2515项目日报260721.xlsx` 非标准封装不可直接解析）。

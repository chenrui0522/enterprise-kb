## Why

演示用的 `seed_org_tree` 只有总经办与少量中心/部门，与企业微信通讯录脱节；注册真实岗位（如项目管理部）时无处可挂。需要把通讯录文件夹全量同步进 `org_units`，并明确「☆太原/朔州/苏州公司」与「泰国公司」的映射，避免把地点标签误建成组织根。

## What Changes

- 以企业微信通讯录为真相源，把公司根下全部办/中心/部/地区分部/组/组内小组写入组织树（本期只建节点，不建用户）。
- 新增公司直属节点「泰国公司」（与总经理办、八中心同级，`type=dept`）。
- 通讯录顶层「☆太原公司 / ☆朔州公司 / ☆苏州公司」**不**建 `org_units`；地点仍只在用户 `site` 上。
- 名称含地名的真实部门照建：苏州销售部、太原销售部（营销/销售部下）、朔州人事行政（运营管理中心下）等。
- **BREAKING（相对演示种子）**：软件部、采购部父节点从生产中心改为产品中心；「总经办」显示名统一为「总经理办」；补齐缺失中心与全量子树；`default_site` 不再暗示「朔州=生产」这类错误归属。
- 授权公式不变：岗位视野仍为本级；不引入子树视野；不建用户账号。

## Capabilities

### New Capabilities

- （无）

### Modified Capabilities

- `identity-access`: 组织树 MUST 与通讯录文件夹一致；泰国公司为真实公司直属节点；太原/朔州/苏州「☆公司」标签 MUST NOT 进树；含地名的部门节点仍为真实 `org_units`；澄清软件部挂靠产品中心等与通讯录一致的父子关系。

## Impact

- 代码：`app/cli.py` 的 `seed_org_tree` / `seed-demo`；可能的一次性迁移脚本或 seed upsert（改名、改父、补节点）；组织相关测试与 README 中的示例树。
- API/模型：`OrgUnit` 表结构与授权公式不变；既有演示用户岗位若挂在旧父节点下需随迁移更新。
- 非目标：用户/岗位导入、子树视野、多租户拆分、把☆公司建成第二公司根。

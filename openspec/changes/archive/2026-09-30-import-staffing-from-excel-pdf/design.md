## Context

人员投入只有一个解析入口：`create_import_batch` 调用 `parse_daily_report`。对话导入也走这个函数。解析器用 openpyxl 在前十几行里按「日期」「现场施工人员」「我司人员」找列，再拆【公司人员】与姓名格。

知识库 PDF 转换（`app/ingestion/converters.py`）会把第一行当成表头并收成 Markdown。这份日报的表头有多行，不能走那条路。`pdfplumber` 已在依赖里，分诊也会用它探测表格。

上传的原始文件已经按批次落盘。对话附件在 `save_chat_xlsx` 里按扩展名拒绝非 Excel。

## Goals / Non-Goals

**Goals:**

- Excel 导出的日报 PDF 在解析前还原成单元格网格，写成内存中的 xlsx，再进入现有 `parse_daily_report`。
- 独立页与对话共用这一步。
- 多页时按纵向续页拼接，并去掉后续页重复表头。

**Non-Goals:**

- 不改复核、确认、工期段、汇总、xlsx 导出。
- 不接受 Word、扫描件、无文字层 PDF，也不做 OCR。
- 不把 PDF 送进 Docling、MinerU 或知识库入库。
- 不处理「一页只有左半表、下一页只有右半表」的横向拆页。

## Decisions

1. **在 `parse_daily_report` 入口把 PDF 收成 xlsx 字节，再走现有逻辑。**
   独立页和对话都只经过 `create_import_batch`。转换放在解析函数开头，两处入口不用各写一遍。落盘仍保存用户上传的 PDF，内存里的 xlsx 只给解析用。
   备选：在 API 层转完再调用解析。对话编排还要再接一次，容易漏。

2. **用 `pdfplumber` 的原始 `extract()` 行，自己写成 xlsx。**
   不调用知识库转换器。那个实现把 `rows[0]` 当表头，会拆掉这份多行表头。人员投入侧按页取出全部单元格（含空格），用 openpyxl 逐格写入。
   备选：Docling 抽表。多一个服务，而且当前客户端要的是 Markdown。

3. **先确认有文字层，再抽表。**
   整份 PDF 抽不出文本时，按无文字层拒绝（扫描件/拍照件），不回退 OCR。抽得出文本但没有表格，或还原后的表找不到「日期」「现场施工人员」时，交给现有无法阅读告警，不写入出勤事实。

4. **只做纵向续页。**
   第 1 页保留全部行。后面每一页若开头若干行与第 1 页表头（第一个能认出日期的数据行之前）文本一致，则丢掉这段重复表头，再往下接数据行。某一页的表里没有「日期」列时，不猜测左右拼接，按无法阅读处理。
   依据：这类日报从 Excel 导出时通常按页向下延续，整表宽度在同一页内。

5. **写入 xlsx 前把认得出的日期归一成日期格。**
   现有 `_as_date` 只接受日期对象以及 `YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY.MM.DD`。PDF 格子常是未补零或带时间的字符串。归一失败就保留原文，让现有「缺日期」告警生效，不另写一套日期规则去猜。

6. **对话附件只放宽扩展名。**
   `save_chat_xlsx` 与两个上传控件同时接受 `.pdf`。函数先不改名。Word 与其它扩展名仍拒绝。

## Risks / Trade-offs

- [无边框导出导致 `find_tables` 为空] → 先用线条策略抽表，失败再试文本策略；仍然没有表则拒绝并说明需上传带表格线的 Excel 导出 PDF。
- [单元格内换行被拆成多行，日期与人名错位] → 不在转换层重排人名；错位会变成缺日期或人名告警，确认前必须复核。用同一份 xlsx 导出的 PDF 做对照测试，锁住「与源表一致」这条。
- [横向拆页] → 本期直接无法阅读，避免把右半页姓名安到错误的日期上。
- [重复表头匹配过宽，误删数据行] → 只删除与第 1 页表头块逐格相同的前缀，不按单个关键字删行。

## Migration Plan

无表结构变更。上线即对新上传的 PDF 生效，已入库的 xlsx 批次不变。回滚时恢复「非 xlsx 即拒绝」即可，不需要迁移数据。

## Why

会话记忆目前只有"最近 N 轮"的滑动窗口，没有长期记忆：跨天或多轮长对话后，早期信息会从窗口滑出并彻底丢失上下文。同时，压缩机制尚未建立，原文缺少"已压缩"标记，无法在保留审计能力的前提下把旧消息移出窗口。需要短期滑动窗口与长期记忆压缩结合，并保证全量原文永久保留在数据库。

## What Changes

- **短期记忆**：保持滑动窗口（最近 N 轮未压缩消息）。
- **长期记忆**：按 **token 预算**触发压缩，把窗口外最旧的一段消息压缩成滚动摘要；摘要记录覆盖的消息范围。
- **原文不删除**：被压缩的消息只标记 `compressed=true` 并移出窗口，原文永久保留在数据库，供审计与回溯。
- **三层拼接**：加载时使用"长期记忆摘要 + 未压缩的最近消息 + 当前问题"构造上下文；查询改写同样使用该上下文。
- **持久化位置**：会话与消息、记忆摘要、LangGraph checkpoint 全部落 PostgreSQL；Redis 仅用于缓存与限流，不保存对话状态。
- **会话标识**：前端必须稳定传递 `session_id`（等同 `conversation_id`），跨页面、跨天、清缓存后仍能恢复同一会话。
- 非目标：层级摘要（摘要的摘要）、跨会话/跨用户记忆、向量化记忆检索。

## Capabilities

### New Capabilities
- 无。

### Modified Capabilities
- `multi-turn-chat`: 会话记忆由单一滑动窗口改为"滑动窗口 + token 预算压缩的长期摘要"，并明确原文保留与会话标识稳定性。

## Impact

- 数据：`messages` 增加 `compressed`、`token_count`、`summary_id`；新增 `conversation_summaries` 表与迁移。
- 服务：新增记忆压缩服务（按 token 预算触发、按会话加锁）；会话加载改为三层拼接。
- 问答链路：改写与生成节点使用摘要 + 窗口；checkpoint 仍落 PostgreSQL。
- 前端：会话标识持久化（URL + localStorage）并显式传递；恢复失败时给出明确提示。
- 测试：新增跨天恢复的自动化验收（清空 Redis、重启服务、同 session_id 继续追问）。

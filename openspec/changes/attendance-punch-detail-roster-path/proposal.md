## Why

运营希望苏州等站点用更少源文件完成考勤汇总：不必每月再导出差申请与请假申请，只要企微「上下班打卡」类导出（打卡详情必选，概况统计可选）加上花名册底表，仍导出与太原一致的一人上下班双行日格与红框汇总。现行三源路径依赖出差类别（项目/非项目）与出差地点字段；打卡详情可用打卡地点区分国内外，且苏州口径不区分项目/非项目——适合增加一条并列输入路径，而不是改掉三源默认规则。

## What Changes

- 新增考勤汇总**并列源路径**（与现有「出差 + 请假 + 打卡详情」三源并存）：
  - **必选**：打卡详情（含上班/下班、状态、打卡地点、假勤申请）+ 花名册底表（prior / 人事冷启动，规则同现）
  - **可选**：概况统计与打卡明细（用于假勤/结果交叉校验或补洞；不得单独作为国内外依据）
- 本路径出勤/出差口径（与三源路径不同，须在任务/UI 上可区分）：
  - 某日**上、下班均有有效打卡**即计该日实出勤（不区分工作日/休息日，不区分项目/非项目）
  - 假勤申请含出差且当天满足上、下班有效打卡时，计入国内或国外出差列（地点取自打卡地点关键字）；**无（或不足）上下班有效打卡时：不计实出勤，也不写出差列**
  - 假种仍从假勤申请（及可选概况表）解析半天/全天，映射太原假种符号与红框列
- 导出仍为太原考勤汇总模板（日格 + 红框）；MUST NOT 因本路径改为苏州一人一行汇总表
- **非目标**：替换或删除三源路径；调休台账；用概况表单独完成国内外判定；在本路径恢复项目/非项目分支

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `attendance-summary-ledger`: 增加「打卡详情 + 花名册（±概况）」源路径的收录、解析与本路径专用出勤/出差计额要求；与三源路径并存且可识别
- `chat-tools`: 对话内考勤汇总工作流支持选择或识别本路径源组合，进度卡与上传角色与专页一致

## Impact

- `app/attendance_summary/parse.py`（打卡详情假勤文本、概况表可选解析；国内外仍可用地点关键字）
- `app/attendance_summary/compute.py` 或本路径专用计额入口（避免静默改写三源默认规则）
- `app/attendance_summary/service.py`、API / 专页 / `attendance_summary_orchestrator`（源角色、缺源校验、路径标识）
- 文员说明与单测；导出模板复用，不新增苏州模板

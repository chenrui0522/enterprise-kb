# ops-observability Specification

## Purpose

为 API 与入库 worker 提供可机关联的结构化运维日志、请求级关联标识、关键业务阶段耗时事件，以及依赖分项健康检查，使运维与研发能在不接入外部 APM 的情况下定位故障与性能瓶颈。

## Requirements

### Requirement: 结构化运维日志
系统 SHALL 以一行一条事件的结构化格式（JSON）向标准输出写入运维日志；每条事件 MUST 包含时间、级别、记录器名称与消息，并在存在关联上下文时包含请求或任务标识。

#### Scenario: 默认 JSON 行输出
- **WHEN** 服务在默认配置下处理请求并写入运维日志
- **THEN** 每条日志为可解析的单行 JSON，且包含级别与消息字段

#### Scenario: 级别可配置
- **WHEN** 运维将日志级别配置为 WARNING
- **THEN** 系统不输出低于 WARNING 的运维日志事件

### Requirement: 请求关联标识
系统 SHALL 为每个入站 API 请求确定一个请求标识：若客户端提供合法的请求标识头则复用，否则生成新标识；该标识 MUST 在响应头中回传，并 MUST 出现在该请求处理期间产生的运维日志中。

#### Scenario: 自动生成并回传
- **WHEN** 客户端未提供请求标识头访问 API
- **THEN** 响应头包含系统生成的请求标识，且该请求的运维日志带有同一标识

#### Scenario: 客户端传入则复用
- **WHEN** 客户端提供合法的请求标识头
- **THEN** 响应头与该请求运维日志使用同一客户端标识

### Requirement: 入库任务可关联
系统 SHALL 在处理文档入库任务时，将任务标识写入该任务期间的运维日志，使一次入库的多个阶段日志可被串起。

#### Scenario: 入库失败可按任务检索
- **WHEN** 某文档版本入库失败
- **THEN** 失败相关运维日志包含同一任务标识，运维可据此过滤出该次入库的阶段记录

### Requirement: 问答关键阶段耗时
系统 SHALL 在知识问答处理路径上记录改写、检索必要性判定、检索（含重排）与生成等关键阶段的运维事件，并 MUST 包含各阶段耗时（毫秒）及成功或失败状态。

#### Scenario: 完整问答路径可还原
- **WHEN** 用户发起一次需要检索的问答且成功返回
- **THEN** 运维日志中可找到带同一请求标识的改写、判定、检索与生成阶段事件及各自耗时

#### Scenario: 阶段失败可定位
- **WHEN** 生成阶段因上游模型超时失败
- **THEN** 运维日志包含带失败状态的生成阶段事件与同一请求标识

### Requirement: 入库关键阶段耗时
系统 SHALL 在文档入库路径上记录分诊、转换、切片、向量化与索引写入等关键阶段的运维事件，并 MUST 包含耗时与成功或失败状态。

#### Scenario: 转换过慢可发现
- **WHEN** 文档转换阶段耗时显著高于其他阶段
- **THEN** 转换阶段运维事件的耗时字段反映该耗时，且与同任务其他阶段事件共享任务标识

### Requirement: 外部模型调用边界可观测
系统 SHALL 在调用生成、向量化或重排等外部模型服务时记录调用边界运维事件，包含服务类别、耗时与成功或失败状态。

#### Scenario: 重排超时可见
- **WHEN** 重排服务调用超时
- **THEN** 运维日志出现失败的重排调用事件及耗时

### Requirement: 敏感信息不得写入运维日志
系统 MUST NOT 在运维日志中写入用户口令、会话令牌、Cookie 或文档全文；对用户问句的记录 MUST 受限（截断或仅元数据），不得默认记录完整长文本。

#### Scenario: 登录失败不泄露口令
- **WHEN** 用户登录失败并产生运维或审计相关记录
- **THEN** 口令明文不出现在运维日志中

### Requirement: 依赖分项健康检查
系统 SHALL 提供健康检查接口，分别报告 PostgreSQL、Redis、Milvus 与模型服务的可用性，并给出整体状态；在 PostgreSQL 不可用时 MUST 使调用方能区分「进程无响应」与「数据面不可用」。

#### Scenario: Redis 正常但向量库不可用
- **WHEN** Redis 可用而 Milvus 不可用
- **THEN** 健康检查响应中 Milvus 分项为失败，整体状态为降级或不可用之一，且 Redis 分项为成功

#### Scenario: 数据库不可用
- **WHEN** PostgreSQL 不可用
- **THEN** 健康检查表明数据面不可用，HTTP 状态码与整体状态足以让编排或探活将其与「仅向量库降级」区分

### Requirement: 人员投入路径关键阶段可观测
系统 SHALL 在人员投入（项目日报导入）路径记录结构化运维事件，至少覆盖：解析完成、项目自动匹配、进入待复核、确认写入、作废执行；事件 MUST 可与同一请求标识关联，并在适用时包含耗时（毫秒）与成功或失败状态。运维日志 MUST NOT 写入日报全文；对现场人员自由文本的记录 MUST 截断或仅元数据。

#### Scenario: 解析与确认可串起
- **WHEN** 用户上传日报并成功确认入库
- **THEN** 运维日志中存在带同一请求标识的解析与确认相关事件，且确认事件反映写入或重叠日作废的数量类摘要

#### Scenario: 作废可观测
- **WHEN** 用户按人或按日作废有效出勤事实
- **THEN** 运维日志出现作废事件，包含作废范围类型与作废条数类字段，且带同一请求标识

#### Scenario: 日报正文不入运维日志
- **WHEN** 解析阶段处理含长段「当天实际完成情况」的日报行
- **THEN** 运维日志不出现该完成情况全文

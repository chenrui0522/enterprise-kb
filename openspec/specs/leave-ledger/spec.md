# leave-ledger Specification

## Purpose

支持运营上传太原公司企微四源导出，按调休台账规则计算可调休与已调休，经告警决议后确认，并导出对齐太原一人多行模板的正式台账。

## Requirements

### Requirement: 加班可调休按双证据日历日计额
系统 SHALL 按场景计加班可调休：
1. **项目实际出差段内**：仅当该日为配置的**法定假日本体日**（如端午当天；不含放假调休连休日），且存在已通过加班申请与对应日打卡、且未被半天冲突阻断时，计 **1** 天；出差段内非该表日期的加班 MUST NOT 计入加班可调休（人工决议除外）。
2. **非项目出差或项目出差段之外**：对每个已通过的加班申请日历日，在存在对应日打卡证据且未被半天冲突阻断时，计 **1** 天。
法定假日配置用于判定项目出差段内可计的加班日，并可标注日期；MUST NOT 对已计日另加额度。缺打卡或申请满日而打卡跨度不足半日阈值时（且该日属于可计场景），系统 MUST 产生阻塞告警且默认该日计额为 0，直至操作者作出决议。

#### Scenario: 双证据加班日记一天
- **WHEN** 某人在非项目出差（或项目出差段外）某日有已通过加班申请且当日存在打卡、且未触发半天冲突告警
- **THEN** 该日加班可调休贡献为 1 天

#### Scenario: 项目出差段内仅法定假日本体计额
- **WHEN** 某人项目实际出差段内端午连休三天均有加班申请与打卡，而法定假日表仅含端午当天
- **THEN** 仅端午当天计入加班可调休 1 天，其余两日不计入

#### Scenario: 缺打卡默认不计
- **WHEN** 某人某日属于可计加班场景（非项目/段外，或段内法定假日）且有已通过加班申请但无对应日打卡
- **THEN** 系统产生缺打卡类阻塞告警，且该日加班可调休贡献为 0

### Requirement: 加班告警决议必须写回可调休额度
系统 SHALL 接受对加班缺打卡与半天冲突告警的决议，并在重算后写回该日加班可调休：`exclude` 为 0、`accept_half` 为 0.5、`accept_full` 为 1。决议 MUST 同时清除对应阻塞告警。对话入口与独立调休台账页 MUST 均提供上述三档操作。系统 MUST NOT 仅清除告警而保持与决议不符的计额。

#### Scenario: 按满日记写回一天
- **WHEN** 操作者对某日缺打卡或半天冲突告警选择按满日记并提交复核
- **THEN** 该日加班可调休为 1，且该告警不再阻塞确认

#### Scenario: 按半日记写回半天
- **WHEN** 操作者对某日加班告警选择按半日记并提交复核
- **THEN** 该日加班可调休为 0.5，且该告警不再阻塞确认

#### Scenario: 排除保持零
- **WHEN** 操作者对某日加班告警选择排除并提交复核
- **THEN** 该日加班可调休为 0，且该告警不再阻塞确认

### Requirement: 确认导出一人多行太原模板形台账
系统 SHALL 在任务确认后导出对齐太原调休台账模板结构的 xlsx：双行表头；每人一个行块，块内按行并列展示项目出差段、加班日与调休假段；姓名、中心、部门、合计可调休天数、合计已休天数、剩余调休天数与备注在人块内纵向合并；合计可调休与合计已休列表头以醒目底色标识。加班行 MUST 按日历日一行（开始日与结束日均为该日），且 MUST NOT 为额度为 0 的加班日占用导出行列。出差行 MUST 反映实际/系统提报起止与该段出差可调休；调休行 MUST 按已计入的调休假段列出起止与已休天数。

#### Scenario: 一人多段占多行
- **WHEN** 某人有两段计额项目出差、两个有额度加班日与一条调休假
- **THEN** 导出台账中该人占多行，出差/加班/调休分列填入，人级合计列合并且数值为各段之和

#### Scenario: 零额度加班不占行
- **WHEN** 某人某加班日经决议排除或仍为 0 额度
- **THEN** 导出台账中不出现该加班日对应行

#### Scenario: 未确认不可按新模板正式导出
- **WHEN** 任务尚未确认
- **THEN** 系统拒绝作为正式台账下载一人多行模板导出

### Requirement: 调休台账须落在运营管理中心组织子树
系统 SHALL 在既有 `leave_ledger:read` / `leave_ledger:write` 校验之外，要求操作者组织范围落在 `ops` 子树（运营管理中心及其下属计划运营部、人力资源管理部、行政部、朔州人事行政），或具备 `users:manage` 以绕过组织闸。不满足组织范围的主体 MUST NOT 创建/上传/复核/确认/作废/导出调休台账任务，MUST NOT 经对话工具认领调休台账。

#### Scenario: 非运营中心不可创建任务
- **WHEN** 具备 `leave_ledger:write` 但不在 `ops` 子树且无 `users:manage` 的用户创建调休台账任务
- **THEN** 系统拒绝创建

#### Scenario: 计划运营部可确认
- **WHEN** 具备 `leave_ledger:write` 且岗位在 `ops_planning` 的用户在告警已决议后确认任务
- **THEN** 系统允许确认（仍受既有告警阻塞规则约束）

### Requirement: 段级合并上月已确认与本月计算结果
系统 SHALL 允许操作者将一份**可作为 prior 的调休台账任务**（同租户下状态为已确认的任务，或经正式导出台账导入的 prior 任务）的快照行与当前**未确认**任务的计算结果按人做段级合并，并把合并结果写回当前任务的计算结果，以便继续告警决议、确认与正式导出。上月来源 MUST 由操作者显式指定为某一 prior 任务，系统 MUST NOT 在未指定时自动选定 prior。当前任务若为 `confirmed` 或 `voided`，或尚无计算结果，系统 MUST 拒绝合并。

合并时系统 SHALL：
1. 按姓名对齐人员；仅一侧出现的人保留该侧行。
2. **项目出差段**：合并两侧 `travel_segments` 的实际区间（并保留对应系统提报区间信息），按既有间隔合并规则并段后，**重算**各段出差可调休额度（30 天块），不得简单相加两侧旧 credit。
3. **加班日**：键为 `(姓名, 日期)`；同键仅保留一条，冲突时**以 prior 快照为准**。
4. **调休假段**：键为 `(姓名, start, end)`；同键仅保留一条，冲突时**以 prior 快照为准**。
5. **出差并集后重审加班**：对步骤 3 得到的加班日，若该日落在并集后的任一项目**实际**出差段内，且该日**不是**配置的法定假日本体日，则 MUST NOT 保留该日加班可调休（从合并结果中去除该加班日）。段外加班日与段内法定假日本体日加班按步骤 3 结果保留。重审 MUST 使用与单次计算相同的法定假日配置。
6. 按合并后段与重审后的加班日重算人级合计可调休、已休与剩余。
7. 丢弃当前任务中、键已在 prior 快照出现的加班类阻塞告警（prior 优先已覆盖）；其余告警保留供继续决议。
8. 在审计中记录 `merged_from_job_id`（所选 prior 任务）。

#### Scenario: 显式选择已确认 prior 后写回本月
- **WHEN** 操作者对本月未确认且已有计算结果的任务指定一份同租户已确认 prior 任务并请求合并
- **THEN** 系统将合并后的人员行写回本月计算结果，且审计含该 prior 的 job id

#### Scenario: 显式选择导入 prior 后写回本月
- **WHEN** 操作者对本月未确认且已有计算结果的任务指定一份经正式导出台账导入的 prior 任务并请求合并
- **THEN** 系统将合并后的人员行写回本月计算结果，且审计含该 prior 的 job id

#### Scenario: 未指定 prior 不可合并
- **WHEN** 操作者请求合并但未提供 prior 任务
- **THEN** 系统拒绝合并

#### Scenario: 已确认本月不可再合并写回
- **WHEN** 本月任务状态为已确认或已作废
- **THEN** 系统拒绝合并写回

#### Scenario: 出差跨月重叠按并集重算额度
- **WHEN** prior 快照与本月结果对同一人存在重叠或相邻的项目出差实际区间，并集后满 30 天块而单侧未满
- **THEN** 合并后该人出差可调休按并集重算后的额度计，而非两侧旧 credit 之和

#### Scenario: 同日加班以上月确认为准
- **WHEN** 同一人同一日历日在 prior 快照与本月结果中均有加班日且额度不同，且该日在并集出差段外（或不在段内非法定日剔除范围）
- **THEN** 合并结果保留 prior 该日额度，本月该日告警若仍存在则不再阻塞（视为已由 prior 覆盖）

#### Scenario: 并集出差段覆盖后剔除连休加班
- **WHEN** prior 快照对某人在端午连休三日（法定假日表仅含端午当天）均有加班可调休，且当时该人不在项目实际出差段内或出差段未覆盖该三日；本月合并后并集实际出差段覆盖该三日
- **THEN** 合并结果仅保留端午当天的加班可调休，连休其余两日不得计入，人级合计随之更新

### Requirement: 列出可选的已确认调休任务
系统 SHALL 提供只读列表，返回当前租户下可用作合并 prior 的调休台账任务：至少包括状态为已确认的任务，以及经正式导出台账导入的 prior 任务（列表项至少含 job id、确认或导入时间，并可区分来源）。列表 MUST NOT 包含作废任务作为可选 prior。

#### Scenario: 选择器可见已确认任务
- **WHEN** 有权限的操作者打开合并 prior 选择
- **THEN** 系统展示本租户已确认任务供点选，且不把已作废任务列为可选 prior

#### Scenario: 选择器可见导入 prior
- **WHEN** 有权限的操作者打开合并 prior 选择且租户存在经正式导出台账导入的 prior
- **THEN** 系统将该导入 prior 与已确认任务一并列出供点选，且可区分来源

### Requirement: 从正式导出台账导入可合并 prior
系统 SHALL 允许有权限的操作者上传一份由本系统确认导出的太原一人多行调休台账 xlsx，将其解析为人员行快照并登记为同租户下可选用的合并 prior 任务。非该正式导出模板结构的文件 MUST 被拒绝，且 MUST NOT 写入可合并 prior。导入 MUST 要求操作者具备调休台账写入权限（及既有组织闸），MUST NOT 因文件名含「台账」等字样自动对本月任务执行合并。

#### Scenario: 上传系统导出台账成功登记 prior
- **WHEN** 操作者上传本系统正式导出台账 xlsx 并请求导入为 prior
- **THEN** 系统登记一份可在 prior 列表中选用的任务，且其中人员行可被后续段级合并使用

#### Scenario: 非导出模板拒绝导入
- **WHEN** 操作者上传无法按正式导出台账结构解析的 xlsx
- **THEN** 系统拒绝导入为 prior，且 MUST NOT 创建可合并 prior 任务

#### Scenario: 仅导入不自动合并
- **WHEN** 操作者完成导出台账导入
- **THEN** 系统 MUST NOT 在未收到显式合并请求时改写任何本月未确认任务的计算结果

### Requirement: 专页可上传正式导出台账作为 prior
系统 SHALL 在独立调休台账页的合并区域提供上传本系统正式导出台账并导入为 prior 的入口，导入成功后操作者可将其选为 prior 并执行与既有一致的段级合并写回。

#### Scenario: 专页上传后可选并合并
- **WHEN** 操作者在专页对当前未确认且已有计算结果的任务上传正式导出台账完成导入，并显式选择该 prior 请求合并
- **THEN** 系统将合并结果写回当前任务，行为与选择系统内已确认 prior 一致

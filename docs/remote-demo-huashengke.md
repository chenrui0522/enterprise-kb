# 远程演示：花生壳内网穿透（dev 模式）

适用场景：本机仍用 `npm run dev`（**未** build 静态托管），临时让同事从外网打开知识库试用。  
**不适合**长期生产；用完请关闭映射。

## 架构（只穿一条隧道）

```
同事浏览器
    |
    |  https://<花生壳公网域名>/
    v
花生壳客户端  ---->  本机 127.0.0.1:5173  (Vite)
                         |
                         |  /api 代理到 127.0.0.1:8000
                         v
                   FastAPI + worker + Postgres/Redis/Milvus
                   （留在内网，不要穿透）
```

依据：`frontend/vite.config.js` 将 `/api` 代理到本机 API，浏览器只访问前端域名即可同源拿到 Cookie 与 SSE。

| 端口 | 是否穿透 | 说明 |
|------|----------|------|
| **5173** | **是** | Vite 开发服务器 |
| 8000 | 否 | API，由 Vite 代理 |
| 5432 / 6379 / 19530 等 | 否 | 基础设施 |

## 演示前检查

1. 本机已启动：compose 依赖、`scripts/init-models.ps1`（或 `.sh`，重启 model-service 后必跑）、`uv run python run.py`、`uv run python -m app.worker`、`cd frontend && npm run dev`。
2. 本机浏览器打开 `http://127.0.0.1:5173`，确认能登录、能问答。
3. 已为同事建好账号（管理端「用户与绑岗」，或 CLI `create-admin`）；按需勾选问答 / 人员投入等权限与项目成员。
4. 数据库若刚拉代码：先 `alembic upgrade head` 再启 API。

## 三步操作

### 1. 本机服务保持运行

演示期间电脑勿休眠、勿关上述进程。

### 2. 花生壳映射

在**同一台跑 Vite 的电脑**上配置：

| 项 | 值 |
|----|-----|
| 内网主机 | `127.0.0.1` |
| 内网端口 | `5173` |
| 外网访问 | 尽量选 HTTPS 域名 |

不要映射 8000 及其它数据库/中间件端口。

若浏览器出现 `Blocked request. This host (...) is not allowed`：确认 `frontend/vite.config.js` 已设置 `server.allowedHosts: true`（仓库已默认打开供演示），然后**重启** `npm run dev` 再刷新公网域名。

### 3. 同事打开的 URL

把花生壳客户端显示的公网地址发给对方，例如：

`https://xxxx.vicp.fun/`

（以客户端实际域名为准，一般打开根路径即可。）

对方打开后进入登录页，使用你事先开好的账号密码。  
**不要**让对方访问 `:8000` 或你的局域网 IP。

## 同事反馈「有的功能不能用」时怎么查

先分清是 **账号权限**、**穿透链路**，还是 **本机服务没起全**。

### A. 权限（最常见）

角色大致能力（以当前 `ROLE_PERMISSIONS` 为准）：

| 能力 | reader（如 seed 的 yuan） | editor（如 seed 的 ma 部分岗） | admin |
|------|---------------------------|--------------------------------|-------|
| 登录 / 问答 | 有 | 有 | 有 |
| 看文档列表 | 有（仍受可见性过滤，可能为空） | 有 | 有 |
| 上传文档 | 无 | 看角色是否含 `documents:write` | 有 |
| 人员投入只读 | 有 | 视绑岗 | 有 |
| 人员投入导入/确认 | 需 `staffing:write` | 视绑岗 | 有 |
| 管理端 | 无 | 无 | 有 |

文档「看得到入口但列表空 / 问答没依据」：不一定是坏了，而是该用户**无权看那些文档**（组织/密级/项目可见性）。

人员投入「按钮灰了 / 403」：检查是否绑了含 `staffing:write` 的岗位，以及是否加了对应**项目成员**。

### B. 穿透与长连接

- 登录失败（401）：密码错、账号锁、或 Cookie 未带上——确认只用公网域名打开（不要混用 localhost）。
- 问答卡住 /「对话中断」：花生壳对 **SSE** 不友好时常见；本机 `127.0.0.1:5173` 正常而公网不行，多半是链路问题。
- 上传一直「排队中」：确认本机 **`uv run python -m app.worker` 在跑**。
- 上传变「失败」/ OCR 后卡住：`curl http://127.0.0.1:9997/v1/models` 应看到 `bge-m3` 与 `bge-reranker-v2-m3`；空列表则跑 `scripts/init-models.ps1`，再在管理端点「重试」。`/healthz` 的 `model_service` 会在模型未加载时标 `fail`。

### C. 本机自检

1. 本机登录同一账号，功能是否正常？正常 → 偏穿透/权限说明；不正常 → 先修本机。  
2. API 日志里看该时段是否有 `401` / `403` / `5xx`。  
3. 演示账号建议单独开，绑好岗位与项目后再发给同事。

- 出现「能打开页但登不上」：确认仍只穿 5173、且本机 Vite/API 都在跑；登录接口走同源 `/api`。
- 出现「对话中断，未收到完整回复」：部分穿透对 SSE 长连接不友好，可换线路/套餐，或改为内网/VPN 演示。
- **演示结束立刻关闭花生壳映射**；勿把默认库口令与弱密码长期暴露在公网。

## 与正式部署的区别

| | 本说明（dev + 穿透） | 正式部署 |
|--|----------------------|----------|
| 前端 | `npm run dev` | build 静态资源 + Nginx 等 |
| 暴露面 | 临时公网域名 | 内网 / VPN / 受控公网 |
| 配置 | 开发默认即可 | 改强密码、关 `AUTO_CREATE_TABLES`、HTTPS、备份 |

账号开通步骤仍以 README「多租户 / 权限」与管理端为准；本页只描述**如何把已有服务临时暴露给外网同事**。
